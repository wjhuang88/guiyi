## Required-test mapping

- Permission denial: a read-only session attempts `document.create`, receives `AGENT_PERMISSION_DENIED`, consumes one action, and records the rejection.
- Working-set read denial: a session restricted to `stage.a` cannot execute `project.document.get` for `stage.b`.
- Working-set mutation denial: the same session cannot set a field in or delete `stage.b`.
- Query visibility: `project.documents.list` returns only documents in a non-empty working set.
- Multi-document command denial: a command requiring `stage.a` and `stage.b` is rejected when only `stage.a` is present.
- Undeclared cross-document mutation: command-level scoped execution compares the real transaction diff before commit and atomically rejects a modification outside the allowed set.
- Budget enforcement: the first call at a budget of one succeeds; the next valid call returns `AGENT_BUDGET_EXCEEDED`, is recorded, and does not increase `actions_used`.
- Exact-budget completion: a scripted driver uses exactly one allowed tool call and then returns `Complete`; the session becomes `Completed` rather than `BudgetExceeded`.
- Failed/rejected action recording: permission, working-set, budget, and missing-tool results are present in session action history.
- Deterministic failure state: a missing tool produces `AGENT_TOOL_NOT_FOUND` and moves the session to `Failed`.
- Workbench integration: Workbench unit coverage routes decoded JSONL calls through the same mutable executor, enforces `--max-actions`, records both the accepted and budget-rejected results, and parses repeated working-set IDs.
