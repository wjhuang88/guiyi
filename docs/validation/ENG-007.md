## Adversarial coverage

Automated tests verify that `ProjectPath` rejects:

```text
../../outside.json
/absolute/outside.json
C:\outside.json
C:/outside.json
content/../outside.json
content//outside.json
content/./outside.json
\\server\share\outside.json
```

Manifest deserialization is tested with a parent-traversing document path and returns `PROJECT_PATH_INVALID` with the rejected logical path.

On Unix-family targets, an adversarial test creates `content/link-to-outside` as a symlink to an external directory. A write through that logical path returns `PROJECT_PATH_ESCAPE`, and the external file remains absent.

Storage lifecycle tests exercise read, write, JSON serialization, rename, delete, and existence checks through the same boundary. CLI tests reject absolute and parent-traversing build output paths. Workbench tests reject an unsafe manifest before attempting an external document read.

## Acceptance mapping

- Absolute document and output paths: rejected.
- Parent traversal: rejected.
- Escaping symlinks: rejected through canonical-root and nearest-existing-ancestor checks.
- Read, write, rename, delete, directory creation, autosave, manifest loading, Workbench persistence, and artifact output: routed through `ProjectFilesystem`.
- External file mutation after an escape attempt: adversarially tested as absent.
- Stable errors: `PROJECT_PATH_INVALID` and `PROJECT_PATH_ESCAPE`, including the logical path.
- Unix/macOS and Windows path forms: forward-slash logical grammar and Windows prefix/backslash forms are tested independently of host parsing; Unix symlink behavior is executed under the Unix test configuration.
- CLI and Workbench failure paths: return errors and do not panic.
