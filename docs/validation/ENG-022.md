## Product direction

This Story advances GUIYI's Agent-first development surface. Dialogue graph authoring, tactical rule discovery, candidate validation, build, and repair evidence are available through typed semantic capabilities. No Editor-only graph, private rule format, or Talos-specific mutation route is introduced.

## Implementation boundary

ENG-022 is contained in the tactical content/validation/tools crates plus existing CLI/example/golden integration. `tactical-rpg-content` reuses internal `guiyi-engine-schema`; reusable engine crates do not depend on tactical code. No external dependency or Talos SDK/version/feature change is introduced.

## Acceptance evidence

### Shared tactical rule registry

- deterministic distinct condition/effect namespaces;
- duplicate registration rejection;
- `SchemaNode` descriptor validation;
- built-ins `always` and backwards-compatible `emit_signal`;
- structured malformed/unknown/schema-invalid invocation diagnostics;
- deterministic `tactical.rules.catalog` machine-readable schemas.

### Stage Trigger compatibility

Existing Trigger serialization and `stage.create_trigger` schema are unchanged. Shared Stage validation now checks Trigger conditions/effects with Stage/trigger/field-path diagnostics. Tests prove historical valid `emit_signal` content remains valid and invalid rule candidates are rejected atomically.

### Dialogue model/compiler

Dialogue documents round-trip through `DocumentEnvelope`; stable node/choice IDs and authored ordering are preserved. Validation covers empty names/text, entry/target integrity, duplicate IDs, shared rules, and non-blocking unreachable warnings. `DialogueCompiler` uses the standard source-hash/integrity path and rejects blocking local failures.

### Semantic Commands and security

`dialogue.create`, `dialogue.add_node`, and `dialogue.add_choice` are schema-bearing live Commands. Tests cover dry-run reviewable diffs, apply, audit/transaction evidence, invalid target/rule atomicity, permission denial, and working-set denial. `tactical.rules.catalog` requires Read, declares no document access, and succeeds for restricted read-only sessions because it does not inspect project documents.

### Build, discovery, and executable proof

CLI recognizes Dialogue documents and registers Stage + Encounter + Dialogue compilers. Strict BuildPipeline tests prove all three artifacts are produced for valid content and no partial artifacts are emitted on blocking Dialogue/rule failure. The command golden grows from 14 to 17. The tactical demo authors Dialogue via semantic Commands and compiles it through the normal build path. Live ToolCatalog coverage proves the existing ENG-014 Talos adapter discovers the new Commands/Query without Talos-specific code.

## Compatibility / migration

Dialogue content and Tool IDs are additive. Stage document serialization is unchanged. Existing valid `emit_signal` rules remain compatible. Previously unchecked malformed, unregistered, or schema-invalid condition/effect payloads may now fail validation intentionally. No second graph/registry persistence truth exists.

## Risks / limitations

The registry validates authoring schema but ENG-022 does not define runtime evaluation/execution semantics. Dialogue artifacts are build outputs only; no conversation VM/session state is introduced. Rule expansion beyond the two minimum generic built-ins remains future game/toolkit work with explicit contracts.

## Rollback

Remove Dialogue content/compiler/validation/Commands/Query/tests/registrations/docs and the shared tactical rule registry integration, including the internal schema dependency/lock update. Existing Stage serialization requires no migration. Rollback must not replace these capabilities with an Editor-private Dialogue graph or alternate unchecked rule format.
