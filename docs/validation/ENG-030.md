## Current delivered integration baseline

The new `guiyi-example-talos-playable-slice` package is a compiled, CI-executed **Talos SDK integration witness**, not the real-model product acceptance. Its `run_with_provider` entry point accepts an operator-supplied Talos `LanguageModel` and uses an actual `RuntimeBuilder`, `RuntimeHandle` and `GuiyiTalosAdapter` to register live schema-bearing GUIYI Commands and Queries. The local CI fixture provider inspects actual returned structured Tool results and does not choose `tactical.make_stage_playable` unless `STAGE_NO_SPAWN_POINT` was observed.

The session exercises existing semantic Stage/Actor/Encounter/Dialogue Commands, `stage.validate`, intent repair dry-run/applied transactions, and three explicit **demo-scoped** Talos operational `AgentTool`s:

1. `demo.project.validate` delegates to existing `validate_stage`, Encounter/Dialogue validators and reference checks.
2. `demo.project.build` delegates to the existing strict GUIYI `BuildPipeline` with Stage, Encounter and Dialogue compilers and actor definition authoring-only; it fails closed on validation errors and an incomplete tactical slice.
3. `demo.stage.preview` accepts only a Stage ID from the latest successful build of **current authoritative persisted documents**, verifies its artifact integrity via `StageRuntimeManager`, and checks repeated load/unload with no remaining `StageOwned` entities or Stage instances.

The operational adapters require `Read` plus the corresponding `RunValidation` / `RunBuild` / `RunPreview` permission. Project-wide scans are denied for restricted working sets before reading project documents. All semantic authoring still uses GUIYI AgentHost, CommandExecutor, transaction/diff/audit and normal ProjectStorage persistence. The ephemeral build cache is derived, content-hash-bound output, **not** an alternative project/build/Stage graph truth. No shell or direct content-file edit Tool is introduced.

The review packet now records observed Tool IDs, live advertised Tool input schemas, structured result statuses and diagnostics, sanitized intent transaction IDs/statuses/diffs, ephemeral build artifact IDs/source/integrity hashes, headless preview outcome, final persisted document IDs, and redacted `ProjectStorage.audit_records` entries. Full document Query outputs and raw conversation transcript are not exported. This packet is review evidence only; persisted project documents and journal remain authoritative.

## Remaining required product acceptance — **not yet satisfied**

**A sanitized real-provider/model-driven Talos execution has not been performed.** The existing executable uses a deterministic fixture `LanguageModel` to make CI repeatable; even though it executes the genuine Talos Runtime/SDK path, it is **not** an actual LLM provider. The operator-facing injection API and invocation boundary are documented in `examples/talos_playable_slice/README.md`, but this execution environment did not supply a real provider and credentials. A real provider smoke run must separately prove live Tool discovery, model-selected diagnostic-driven repair with dry-run/apply, strict build and headless preview, and durable reviewable audit. It must not print credentials or raw private project data.

Until this requirement and final clean-head full CI are satisfied, **ENG-030 stays Ready, Issue #72 stays open, and PR #74 stays draft/unmerged**. No claim of a production-complete Talos playable slice is made.

## Compatibility / migration / ADR

The only added integration surface is the example package and an outer-SDK type re-export `guiyi_talos_runtime::sdk` to keep `talos-runtime` a direct dependency of **only** `integrations/talos_runtime`. Existing typed Commands/Queries, Stage/Encounter/Dialogue/rule schemas, project persistence, Project Graph, runtime artifacts, Talos SDK version and features are unchanged. No content migration is needed. The scoped demo Tools are not a stable engine-core Tool catalog or second graph/persistence authority. No new ADR is required under this boundary; any stable public general build/preview Tool requires separate change-control.

## Rollback

Remove `examples/talos_playable_slice`, the workspace member/Cargo.lock stanza, the new CI example command, `guiyi-talos-runtime::sdk` re-export (actual crate `guiyi_talos_runtime`), and this Story's docs. Leave existing GUIYI semantic Tools, Talos integration adapter, engine runtime, and persisted project schemas untouched. Do not replace this proof with direct private-file authoring or Editor-only state.
