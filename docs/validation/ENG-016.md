# ENG-016 validation

## Implemented behavior

`BuildPipeline::new` now creates a strict authoritative build boundary. The pipeline validates all document references before compilation, treats undeclared missing compilers as blocking errors, withholds every artifact when any blocking diagnostic exists, and reports every skipped document with a structured reason.

`BuildProfile` supports explicit authoring-only document types. These documents are reported and skipped without failing a build. A non-strict compatibility profile remains opt-in; missing compilers are warnings in that mode and are never silently ignored.

`BuildReport` includes artifacts, diagnostics, and `SkippedDocument` entries with document ID, type, reason, and message. `BuildReport::succeeded()` is false whenever errors exist.

## Coverage

Tests cover:

- strict missing-compiler failure;
- unresolved document reference failure before compilation;
- explicitly authoring-only documents;
- compiler failure;
- withholding earlier successful artifacts after a later failure;
- opt-in compatibility mode reporting;
- deterministic empty build success.

The tactical demo now inserts its referenced Actor Definition and explicitly classifies that definition type as authoring-only, so it succeeds under the same strict library semantics used by CLI callers.
