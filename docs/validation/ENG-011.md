# ENG-011 validation

## Story

ENG-011 adds crash-safe `ProjectStorage` and a persistent transaction journal for project mutations.

## Implemented boundary

- Unique same-directory temporary files replace fixed `.tmp` names.
- Multi-file changes persist before/after snapshots and a write-ahead journal.
- Non-manifest operations are applied before the manifest.
- Journals retain transaction ID, session ID, actor, audit sequence, structured report, operation kind, logical path, and snapshots.
- Startup recovery rolls back incomplete transactions and restores audit records for committed transactions.
- CLI initialization and build output, JSONL Workbench persistence, and authoring autosave use `ProjectStorage` transactions.
- Storage errors expose stable codes and logical operation context.

## Failure-injection evidence

`guiyi-engine-content` tests simulate failures at:

- after journal preparation;
- after the applying marker;
- after each non-manifest operation;
- before the manifest;
- after the manifest;
- after the commit marker;
- after audit persistence.

Pre-commit failures restore the previous document and manifest state after restart. Failures after the commit marker preserve the new state and recreate any missing audit record. Repeated recovery is idempotent.

Additional tests verify successful restart persistence, duplicate-target plan rejection, unique temporary cleanup, durable autosave audit records, and normal Workbench/CLI behavior through the shared boundary.

## Platform guarantee

The implementation synchronizes temporary file contents and containing directories around replacement. Unix uses same-directory atomic rename. Windows uses a unique backup and restores it if replacement fails. The guarantee is single-process and single-writer; distributed, remote, and multi-user transactions are outside ENG-011.
