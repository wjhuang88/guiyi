# ENG-020 validation — tactical navigation and reachability

## Story

- Story: ENG-020
- GitHub Issue: #59
- Implementation PR: #61
- Primary ownership: GUIYI tactical-RPG toolkit (`content`, `validation`, `tools`)
- Authorized base: governance PR #60, main `2da2e99158817c64e45eac6e520b0567e3132955`

## Product-direction contribution

ENG-020 advances GUIYI's Agent-first development surface. Navigation painting and traversability inspection are normal game-development tasks that a traditional engine Editor commonly mediates. GUIYI therefore exposes them as typed machine-facing authoring/query capabilities rather than reserving navigation state for a GUI-only editor subsystem.

A future spatial Editor may visualize blocked cells, paths, diagnostics, and transaction diffs, but it must invoke the same authoritative Commands and Queries. It does not own a second navigation file, graph, or mutation model.

No new ADR is required. ENG-020 applies the accepted typed-command, diagnostics, headless-first, toolkit-ownership, and Agent-first/editor-as-client decisions without changing dependency ownership.

## Implemented boundary

### Stage navigation authoring model

`StageDocument` now contains defaulted `StageNavigation { blocked: Vec<HexCoord> }` authoring data.

Properties:

- `#[serde(default)]` keeps pre-ENG-020 Stage payloads readable without migration;
- the Stage coordinate space remains the bounds authority;
- blocked cells live in the Stage document rather than a second navigation file or persisted graph;
- `StageCompiler` preserves navigation data in Stage artifact metadata;
- semantic mutation keeps the normal authored blocked-cell list deterministic.

### Deterministic reachability

The tactical content crate provides reusable deterministic unweighted grid traversal:

- HexAxial and Square coordinate spaces are supported;
- breadth-first search returns a shortest path;
- fixed neighbor order makes equal-length path selection deterministic;
- blocked and out-of-bounds cells are not traversable;
- start/goal bounds are checked;
- `Free2d` / `Free3d` return `NavigationError::UnsupportedCoordinateSpace` rather than pretending to have grid semantics.

This logic remains in the tactical content crate. No generic engine-core pathfinding subsystem or external dependency was introduced.

### Shared validation

`validate_stage` now emits stable machine-readable navigation diagnostics:

- `STAGE_NAV_BLOCKED_CELL_OUT_OF_BOUNDS` — error;
- `STAGE_NAV_DUPLICATE_BLOCKED_CELL` — warning;
- `STAGE_NAV_SPAWN_BLOCKED` — error;
- `STAGE_OBJECT_UNREACHABLE` — error when a non-spawn object is unreachable from every spawn on an otherwise structurally valid grid Stage;
- `STAGE_NAV_UNSUPPORTED_COORDINATE_SPACE` — error when blocked-cell data is used on a free-space Stage.

Existing Stage diagnostics remain intact.

### `stage.set_navigation_blocked`

Inputs: `stage_id`, `q`, `r`, `blocked`.

The Command:

- requires `EditContent`;
- declares access only to the target Stage;
- blocks/unblocks one in-bounds grid coordinate idempotently;
- validates the candidate Stage through the shared validator;
- uses the normal GUIYI dry-run, transaction, diff, audit, persistence, permission, and working-set path;
- does not create a Talos-specific or Editor-specific mutation route.

A block that would make authored Stage content unreachable is rejected atomically through `STAGE_OBJECT_UNREACHABLE` rather than committing a broken candidate.

### `stage.reachability`

Inputs: `stage_id`, `from_object_id`, `to_object_id`.

The Query:

- requires GUIYI `Read` + `RunValidation` authority;
- declares access only to the target Stage;
- resolves stable object IDs to Stage coordinates;
- returns `reachable`, deterministic shortest `distance`, and deterministic `path` for reachable grid endpoints;
- returns `reachable=false`, `distance=null`, and an empty path for a disconnected grid;
- returns machine-readable diagnostic results for missing object IDs (`STAGE_OBJECT_NOT_FOUND`), unsupported free-space coordinates (`STAGE_NAV_UNSUPPORTED_COORDINATE_SPACE`), and out-of-bounds endpoints (`STAGE_NAV_ENDPOINT_OUT_OF_BOUNDS`).

Tactical domain-invalid/unsupported Query outcomes are encoded in the Query result instead of adding a tactical-specific branch to the generic engine `QueryError` / AgentHost protocol. Permission and working-set failures remain generic GUIYI `AgentHost` rejections before execution.

## Machine-facing API changes

New live Tool IDs:

- Command: `stage.set_navigation_blocked`
- Query: `stage.reachability`

The CLI command-schema golden intentionally grows from 10 to 11 Commands and includes the new Command schema. The Query is registered in the same live tactical Query registry used to construct GUIYI's Tool catalog. The ENG-014 Talos adapter consumes that live catalog, so no Talos-specific registration was added.

Direct Workbench/CLI/AgentHost/toolkit clients remain Talos-independent.

## Acceptance evidence

### A. Backward compatibility

`toolkits/tactical_rpg/content/tests/navigation.rs` constructs a legacy Stage envelope with no `navigation` member, deserializes it with an empty default navigation model, and compiles it successfully.

The repository's existing sample Stage JSON is intentionally not migrated merely to make ENG-020 work; existing examples continue to exercise old payload compatibility.

### B. Deterministic path semantics

Content tests prove:

- Hex BFS routes deterministically around a blocked coordinate;
- Square BFS uses stable neighbor order for equal-length alternatives;
- free-space coordinates return an explicit unsupported error.

### C. Navigation diagnostics

Validation tests prove:

- out-of-bounds blocked cells produce `STAGE_NAV_BLOCKED_CELL_OUT_OF_BOUNDS`;
- duplicate blocked cells produce one deterministic warning for the duplicate occurrence;
- blocked spawn points produce `STAGE_NAV_SPAWN_BLOCKED` with object location;
- a grid wall that disconnects an authored object produces `STAGE_OBJECT_UNREACHABLE` with that object's location.

### D. Command transaction behavior

Tool integration coverage proves:

- dry-run returns a preview transaction and reviewable Stage document diff while authoritative state remains unchanged;
- applied block/unblock operations produce normal applied transaction evidence;
- repeating the same block operation is idempotent (`changed=false`) and produces no document diff;
- invalid bounds are rejected atomically;
- a candidate block that disconnects an authored object is rejected atomically with `STAGE_OBJECT_UNREACHABLE`;
- rejected validation paths do not append command audit records;
- successful/previewed paths retain normal audit evidence.

### E. Query behavior

Tool integration coverage proves:

- a reachable object pair returns deterministic shortest path and distance;
- a disconnected pre-existing Stage returns `reachable=false` without inventing a path;
- an unknown stable object ID returns structured `STAGE_OBJECT_NOT_FOUND` output;
- a `Free2d` Stage returns structured `STAGE_NAV_UNSUPPORTED_COORDINATE_SPACE` output.

### F. AgentHost security and live discovery

AgentHost coverage proves:

- read-only callers cannot invoke the mutating navigation Command;
- read-only callers lacking `RunValidation` cannot invoke the reachability Query;
- a content author whose working set excludes the target Stage cannot mutate it;
- authoritative state remains unchanged on permission/working-set rejection;
- both Tool IDs are present in the live combined Tool catalog with machine-readable input schemas;
- an authorized AgentHost call can execute `stage.reachability` and receive the structured result.

## Compatibility / migration

- Existing Stage JSON without `navigation` remains readable and buildable.
- No standalone navigation document/artifact or persisted graph truth is introduced.
- Stage artifact metadata adds authored navigation data; the normal artifact envelope/type/version contract is unchanged.
- Existing Tool IDs and schemas remain unchanged.
- Additive Tool IDs only: `stage.set_navigation_blocked`, `stage.reachability`.
- CLI capability consumers must tolerate the command catalog growing from 10 to 11 entries.
- No Talos dependency/version/feature change.
- No new external dependency.
- Reusable engine crates do not depend on tactical toolkit code.

## Risks / limitations

- Navigation is unweighted grid reachability only; it does not model terrain cost.
- Authored Stage objects do not dynamically block traversal.
- There is no runtime path-following/movement AI.
- There is no line-of-sight, cover, tactical turn legality, jump/fly/swim mode, or navmesh generation.
- `STAGE_OBJECT_UNREACHABLE` validates reachability from at least one authored spawn, not game-specific faction/entry rules.
- Domain-invalid reachability Query outcomes use structured Query output rather than extending the generic engine Query error taxonomy in this Story.

These limits are intentional ENG-020 boundaries, not hidden runtime assumptions.

## Rollback

Remove the defaulted Stage navigation field, deterministic traversal helper, navigation validator additions, the two Tool registrations/handlers, ENG-020 tests, command-schema golden entry, and ENG-020 documentation.

Pre-ENG-020 Stage payloads require no migration. Content authored with ENG-020 blocked cells would lose that additive authoring information under rollback, so rollback must be explicit rather than silently replacing it with an Editor-private navigation representation.
