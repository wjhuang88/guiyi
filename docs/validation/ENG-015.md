# ENG-015 validation

## Implemented behavior

`ToolCatalog::from_registries` now returns `Result<ToolCatalog, ToolCatalogError>` and never overwrites an existing descriptor. A collision returns stable code `TOOL_CATALOG_ID_COLLISION` together with the Tool ID, existing kind, and incoming kind.

Command and query registries continue to reject duplicate IDs within their own kind. Catalog construction additionally rejects cross-kind collisions and defensively rejects repeated descriptors of the same kind. Valid catalogs retain deterministic `BTreeMap` ordering.

CLI capability discovery and JSONL Workbench startup propagate catalog errors and exit before starting a session. AgentHost tests and examples explicitly assert that their built-in registries are unique.

## Tests

- valid command/query catalogs combine successfully and list IDs deterministically;
- command/query cross-kind collisions identify both conflicting kinds;
- repeated same-kind descriptors are rejected rather than overwritten;
- all CLI, Workbench, AgentHost, and example callers compile against the fallible constructor.
