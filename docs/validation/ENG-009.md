## Process-level acceptance coverage

The Workbench binary is launched as a child process with piped stdin, stdout, and stderr. Tests verify complete process behavior rather than only calling an internal helper.

### Unknown tool and continuation

Input:

```jsonl
{"id":"1","tool":"missing.tool","input":{},"dry_run":false}
{"id":"2","tool":"project.documents.list","input":{},"dry_run":false}
```

Assertions:

- process exits successfully;
- stdout contains exactly two JSON lines;
- the first result preserves `call_id: "1"`, uses `status: "rejected"`, and reports `AGENT_TOOL_NOT_FOUND`;
- the second result preserves `call_id: "2"` and succeeds;
- stderr is empty.

### Invalid input and validation diagnostics

A `project.document.get` call without `document_id` returns a structured rejection with `AGENT_ACCESS_PLAN_INVALID`. A following invalid `stage.create` call returns a structured rejection with a non-empty diagnostics array. A third `project.documents.list` call succeeds in the same process.

### Permission denial

A read-only Workbench receives `document.create`, returns `AGENT_PERMISSION_DENIED`, and successfully processes a following read query.

### Invalid ToolCall shape and call-ID preservation

A syntactically valid JSON object with string ID `kept-id` but a non-string `tool` field returns `PROTOCOL_INVALID_CALL` and preserves `call_id: "kept-id"`. The following valid query succeeds.

### Host infrastructure failure

Launching the Workbench against a missing project root:

- exits with a non-zero status;
- writes no stdout JSONL;
- writes the host-level `workbench failed` message to stderr.

This proves that ordinary tool outcomes remain distinct from an unusable host process.

## Library-level behavior

Agent Host tests verify that an unknown tool is recorded as a rejected action, leaves the session `Running`, and permits a subsequent valid call. Protocol parsing separates malformed JSON (`PROTOCOL_INVALID_JSONL`) from a syntactically valid but invalid call (`PROTOCOL_INVALID_CALL`).

## Result

ENG-009 satisfies its acceptance criteria on the recorded CI run. Every non-empty input line receives one machine-readable result while the Workbench remains alive for recoverable protocol and tool errors. Host-level project and I/O failures remain process-terminating failures.
