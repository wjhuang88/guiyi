## Scoped implementation

No engine production behavior, protocol contract, content schema, Talos SDK, build dependency direction or runtime API changed. All changes are tests:

1. `crates/engine_cli/tests/process_cli.rs` uses the real Cargo-provided `CARGO_BIN_EXE_guiyi-engine-cli` binary. Checks machine-readable capability JSON, init, validate, successful Stage compile/persist and error exits; rejects invalid output traversal before emitting artifacts. Success stdout is JSON with empty stderr; project/compile failures report nonzero exit and stderr without fake successful JSON.
2. `crates/engine_preview/tests/process_preview.rs` invokes `CARGO_BIN_EXE_guiyi-engine-preview` with a valid, integrity-stamped `ArtifactEnvelope::new` Stage payload matching the existing Stage compiler envelope contract and with missing / tampered / wrong-type fixtures. Checks JSON, exit status, output channels and exact stable failure codes (`PREVIEW_ARTIFACT_READ_FAILED`, `RUNTIME_ARTIFACT_INTEGRITY_FAILED`, `RUNTIME_ARTIFACT_TYPE_MISMATCH`), all without window setup. The envelope is constructed through existing common artifact API rather than creating an illegal engine-preview → tactical toolkit dependency. It is a *compiler-compatible test fixture*, not a claimed direct `StageCompiler` invocation in this specific subprocess test. The separate CLI subprocess test executes the actual strict Stage compiler.
3. `crates/engine_agent_host/src/lib.rs::tests::exhausted_driver_marks_session_failed_without_losing_action_history` exercises the existing scripted driver error branch after exactly one successful Tool. Asserts terminal `Failed`, action count/records, retained error summary and unchanged authoring state.
4. `crates/engine_query/src/lib.rs::tests::get_missing_document_and_successful_queries_preserve_authoritative_state` exercises a missing document's existing `QueryError::Failed` plus a successful get; asserts both leave `DocumentStore` unchanged and returned JSON uses the public document envelope.

The preview executable reports Bevy's allocated entity-table count, not exactly the number of `StageOwned` objects. An initial test incorrectly required `entity_count == 1` and observed 4. ENG-019 adjusted **the test assertion only** to demand a positive count, without silently modifying production runtime semantics. A future stable field-contract change needs its own Story.
